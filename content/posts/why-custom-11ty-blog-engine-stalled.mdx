Building a personal blog should be a straightforward way to share ideas, yet Ben found himself trapped in a maze of scripts, front‑matter, and folder gymnastics. He crafted an 11ty‑based static site with custom CSS, image pipelines, and a one‑command deploy, only to realize the tooling itself was the barrier to writing. The result? A perfectly engineered site that never saw a post, highlighting a classic case of over‑engineering.

<Callout type="takeaway">Over‑engineered tooling can kill the very productivity it aims to boost.</Callout>

## What happened
Ben’s blog started as a minimalist 11ty project, complete with custom scripts for image handling, markdown conversion, and a single npm deploy command. The workflow required creating a new folder, a matching markdown file, and duplicate front‑matter entries for each post, which quickly became tedious.

When he tried to simplify the process by building his own static site generator, the complexity exploded: he needed to parse front‑matter, generate indexes, create RSS feeds, filter drafts, and implement hot‑reload. The effort to maintain the generator eclipsed the time left for actual writing, and the project stalled.

## Why it matters
For solo developers and hobbyists, the allure of a perfectly tuned toolchain can distract from the core goal—creating content. When the setup consumes more mental bandwidth than the output, the project stalls, leading to wasted effort and missed opportunities to engage an audience. This pattern is common across indie tech projects, where the “build the tool” mindset overshadows the product’s purpose.

## How to think about it
Start by defining the primary goal: publishing content. Choose a proven platform (e.g., 11ty, Hugo, or a hosted CMS) that meets that goal with minimal friction. If customization is needed, layer it incrementally—add a script or plugin only after the basic publishing flow works smoothly. Regularly audit your toolchain: if a step adds more than a few minutes of effort per post, consider simplifying or automating it. Keep the focus on output, not on perfecting the underlying engine.

<Callout type="warning">Avoid adding new build steps until you have at least one published post; otherwise, the tool becomes a barrier rather than an enabler.</Callout>
